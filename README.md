# Persistor

**Persistor** — Android-приложение для съёмки и подготовки фотографий документов к отправке. Оно помогает выбрать снимки из одной или нескольких папок, сжать их выбранным кодеком, собрать ZIP-архив и открыть письмо с вложением в Gmail.

Приложение также включает камеру с выбором доступного заднего объектива и размера кадра. Persistor не выравнивает перспективу документа, не распознаёт текст и не отправляет письма без участия пользователя.

## Возможности

- Выбор нескольких исходных папок через системный выбор Android и просмотр изображений в сетке миниатюр. Можно отметить отдельные снимки или выбрать все найденные.
- Выбор отдельной папки для обработанных изображений и отдельной папки для ZIP-архивов. Выбор папок и настройки сохраняются между запусками.
- Девять режимов сохранения: Android JPEG, JPEGli, MozJPEG, WebP, JPEG XL, HEIF/HEIC, AVIF, TIFF CCITT Group 4 и JBIG2.
- Для цветных кодеков — подбор качества по целевому SSIM. Для документных TIFF G4 и JBIG2 — создание однобитного чёрно-белого изображения.
- Создание папки и архива с датой. Если такое имя уже занято, используется суффикс `_2`, `_3` и далее, без перезаписи прежнего результата.
- Проверка ZIP перед очисткой: валидность структуры, полный список записей, размеры и CRC32 содержимого каждого файла.
- Фоновая обработка с уведомлением о прогрессе. Её можно продолжить после сворачивания приложения.
- Встроенная камера: доступные задние объективы, выбор разрешения, пользовательский размер с центральной обрезкой, вспышка-фонарик, фокус по касанию и экран просмотра снимков.
- Список адресатов и тема письма с подстановкой `{date}`. После обработки Gmail открывается с подготовленным ZIP-вложением; отправку подтверждает пользователь.
- История созданных архивов, настройка светлой/тёмной темы и быстрый режим с пятисекундным отсчётом перед обработкой всех найденных изображений.

## Поддерживаемые форматы

| Режим | Выход | Примечания |
|---|---|---|
| JPEG (Android) | `.jpg` | Системный Android JPEG-кодек. |
| JPEGli | `.jpg` | Нативная библиотека JPEGli; результат остаётся обычным JPEG. |
| MozJPEG | `.jpg` | Отдельная нативная библиотека; результат остаётся обычным JPEG. |
| WebP | `.webp` | Кодируется Android. Совместимость просмотра зависит от приложения-получателя. |
| JPEG XL | `.jxl` | Используется встроенная библиотека. Системная поддержка Android и галерей не гарантируется. |
| HEIF/HEIC | `.heic` | Требуется Android 10 или новее и совместимый кодек устройства. |
| AVIF | `.avif` | Требуется Android 14 или новее и доступный кодек устройства. |
| TIFF G4 | `.tif` | Одностраничный чёрно-белый TIFF с CCITT Group 4. |
| JBIG2 | `.jb2` | Одностраничное JBIG2-кодирование; поддержка обычными галереями ограничена. |

Для JPEG, JPEGli, MozJPEG, WebP, JPEG XL, HEIF и AVIF Persistor ищет наименьшее качество, при котором декодированный результат достигает выбранной цели SSIM. Диапазон настройки цели — **0,90–0,99**, значение по умолчанию — **0,95**. Внутренний поиск качества ограничен диапазоном 40–95 и максимум восемью итерациями. Если цель не достигнута, приложение использует качество 95 и добавляет предупреждение. У JPEG XL для проверки SSIM применяется декодер JXL; для остальных цветных кодеков используется декодирование Android. Если кодек устройства недоступен или результат не удаётся декодировать для проверки, обработка сообщает об ошибке, а не подменяет выбранный формат другим.

SSIM — метрика сходства изображений, а не проверка распознаваемости текста. Используемая реализация упрощённая и оценивает яркость по блокам, поэтому высокий SSIM сам по себе не гарантирует идеальную читаемость мелкого шрифта. При необходимости следует проверить итоговый документ визуально.

TIFF G4 и JBIG2 сначала превращают фото в однобитное изображение по фиксированному порогу яркости 160. Цвет и полутона теряются; для этих режимов подбор SSIM и качества не выполняется. Они предназначены для страниц с текстом и графикой, а не для фотографий. Даже при включённом удалении исходников Persistor сохраняет цветные оригиналы при обработке в TIFF G4 или JBIG2.

При сохранении в JPEG, если новое кодирование оказалось не меньше исходного JPEG-файла, Persistor копирует исходные JPEG-байты вместо увеличенного результата. Разрешение уже выбранных для обработки фотографий не меняется; пользовательский размер и обрезка относятся к снимкам, сделанным встроенной камерой.

## Как проходит обработка

1. Выберите исходные папки, отметьте изображения, задайте папку для результатов и папку для ZIP.
2. Выберите формат и при необходимости измените целевой SSIM.
3. Persistor читает выбранные изображения, учитывает ориентацию EXIF и кодирует их. Новые файлы получают расширение и MIME выбранного формата.
4. Создаётся папка вида `ГГГГ-ММ-ДД` и ZIP вида `ГГГГ-ММ-ДД.zip`. Внутри архива файлы размещаются в одноимённой папке. Для уже существующего имени выбирается следующий свободный суффикс.
5. Перед очисткой приложение копирует ZIP во временный файл и проверяет его записи потоковым чтением. Сверяются ожидаемые имена, наличие и отсутствие лишних или дублирующихся файлов, размер каждого содержимого и CRC32.
6. Если проверка не прошла, ZIP удаляется, исходные фотографии не удаляются, а сжатые файлы остаются в папке результатов. Если проверка успешна, при включённых настройках можно удалить папку результатов и исходные фотографии.
7. Показывается размер и итог обработки. Для ZIP больше 17 МБ отображается предупреждение о возможном ограничении почтовых вложений.

ZIP создаётся без дополнительного сжатия содержимого: повторное сжатие уже закодированных изображений обычно не даёт пользы. Проверка CRC выполняется независимо от этого.

## Камера

Экран камеры использует Android Camera2 и сохраняет снимки в одну из настроенных исходных папок в формате JPEG. Доступные объективы определяются по возможностям устройства; их названия показывают идентификатор и приблизительное эквивалентное фокусное расстояние. На конкретном телефоне список объективов, разрешений и вспышки может отличаться.

Можно выбрать один из размеров, предоставленных камерой, или задать пользовательские ширину и высоту. Пользовательский кадр формируется центральной обрезкой и изменением размера. Камера также поддерживает фонарик (если он есть), касание для выбора области фокуса, поворот интерфейса по датчику, просмотр последних снимков и диагностику доступных камер. Режим «Чистая» просит поддерживаемые камерой настройки с минимальным шумоподавлением и повышением резкости; производитель устройства всё равно может влиять на обработку.

Для съёмки требуется разрешение Android на использование камеры. Камера не обязательна для установки приложения: Persistor можно использовать только для обработки уже имеющихся изображений.

## Gmail и статистика

Persistor передаёт ZIP во внешнее почтовое приложение через `FileProvider`. По умолчанию запускается Gmail; если он недоступен, Android показывает системный выбор приложения. Адресаты и тема подставляются заранее, а архив прикрепляется к письму. **Нажать «Отправить» нужно самостоятельно.** Приложение не получает надёжного подтверждения фактической отправки, поэтому история отмечает открытие Gmail с вложением, а не доставку письма.

В истории сохраняются имя архива, дата и время обработки, размер, число файлов, выбранные адресаты и момент открытия Gmail. Историю можно очистить, не удаляя сами архивы.

## Настройки

- Целевой SSIM: 0,90–0,99; по умолчанию 0,95.
- Удаление временной папки после успешной проверки ZIP: включено по умолчанию.
- Удаление исходных фотографий после успешной проверки: выключено по умолчанию. При TIFF G4/JBIG2 оригиналы сохраняются всегда.
- Быстрый режим: выключен по умолчанию; после запуска отсчитывает пять секунд, затем обрабатывает все найденные изображения.
- Автоматически открыть Gmail после обработки: включено по умолчанию, если выбраны адресаты.
- Тема письма: `Документы {date}`; `{date}` заменяется датой архива.
- Тема интерфейса: светлая, тёмная или системная.

Настройки по умолчанию можно изменить в приложении. Они сохраняются локально.

## Сборка и тесты

Для сборки нужны Android SDK с Android 14 / API 34, JDK 17, Gradle Wrapper 8.7, Android Gradle Plugin 8.6.1, Kotlin 2.2.20, Android NDK `27.2.12479018` и CMake `3.22.1`. Native-библиотеки собираются для `arm64-v8a`, `armeabi-v7a` и `x86_64`.

Из корня проекта:

```bash
./gradlew testDebugUnitTest
./gradlew assembleDebug
```

В Windows используйте `gradlew.bat` с теми же задачами. Debug APK создаётся по пути `app/build/outputs/apk/debug/app-debug.apk`.

GitHub Actions запускает unit-тесты и собирает debug APK при push, pull request или вручную из вкладки **Actions**. APK доступен как временный workflow artifact для тестирования.

В репозитории не хранится ключ подписи релизной версии. Debug APK предназначен для проверки; выпуск production APK или публикация в Google Play требуют отдельной release-подписи, сохранённой вне репозитория. CI создаёт debug-подпись на временном runner, поэтому для установки поверх APK с другой подписью сначала удалите старую тестовую копию (её локальные настройки при этом потеряются).

Unit-тесты проверяют CRC-проверку ZIP и метаданные/ключи режимов сжатия. Успешная сборка подтверждает компиляцию приложения и native-библиотек, но сама по себе не проверяет доступность системных HEIF/AVIF-кодеков на каждом телефоне. Эти режимы нужно проверять на целевом устройстве.

## Конфиденциальность и разрешения

Доступ к файлам предоставляется через системный выбор папок Android (Storage Access Framework); приложению не нужен общий доступ ко всему хранилищу. Камера запрашивает отдельное разрешение. Уведомления и foreground service используются для показа и продолжения фоновой обработки; WakeLock помогает не прерывать её при выключенном экране.

Фотографии и архивы обрабатываются локально. Чтобы отправить ZIP, пользователь сам открывает Gmail или другое выбранное Android приложение и подтверждает отправку. Не выбирайте удаление исходников, если вам нужна их отдельная резервная копия.

## Ограничения

- Качество и скорость кодирования зависят от устройства и выбранного формата. HEIF и AVIF требуют соответствующих системных кодеков.
- JPEG XL, JBIG2 и TIFF могут не открываться в стандартной галерее телефона. Для проверки используйте приложение с поддержкой конкретного формата.
- Бинаризация TIFF G4/JBIG2 необратимо теряет цвет и полутона; алгоритм не выполняет OCR, обнаружение границ страницы или коррекцию перспективы.
- Очень большие изображения могут потребовать больше памяти, чем доступно устройству; в таком случае обработка завершится ошибкой.
- Быстрый режим берёт все изображения, найденные в выбранных исходных папках. Если оригиналы оставлены, при следующем запуске снимки могут попасть в новый архив повторно.
- Предупреждение для архивов больше 17 МБ — ориентир, а не гарантия принятия конкретным почтовым сервисом.
- Реальные возможности камеры, разрешения и форматных энкодеров зависят от модели телефона и версии Android.

## Основные технологии

- Kotlin, Jetpack Compose и Material 3.
- Android Camera2 API; Storage Access Framework и AndroidX `DocumentFile`.
- DataStore Preferences для настроек и истории.
- Android `Bitmap` APIs, AndroidX ExifInterface и библиотека Coil для миниатюр.
- JPEGli, MozJPEG, JPEG XL, libtiff, Leptonica и jbig2enc для соответствующих режимов.
- AndroidX HeifWriter / AvifWriter и платформенные кодеки для HEIF/AVIF.
- C++/JNI и Android NDK для нативных кодеков.
- Gradle Wrapper для воспроизводимых команд сборки и unit-тестов.

Лицензионные уведомления включённых сторонних компонентов находятся в `app/src/main/assets/THIRD_PARTY_NOTICES.txt`. Отдельная лицензия на весь проект Persistor в репозитории не указана.
